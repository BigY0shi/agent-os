# v1.1 — Agent harness integration

**Status:** In progress (first slice shipped)  
**Stack:** Hermes Workspace `192.168.0.168`, Honcho `192.168.0.99:8000`, OpenClaw (optional)

## Goals

Wire the Agent OS control plane to Proxmox LXC runtimes: link-out, bundle export, Honcho memory bridge, heartbeats, and per-agent run history.

## Environment

```bash
# Hermes Workspace LXC
AGENT_OS_HERMES_UI_URL=http://192.168.0.168:3000
AGENT_OS_HERMES_GATEWAY_URL=http://192.168.0.168:8642

# Honcho memory LXC (separate from Hermes)
AGENT_OS_HONCHO_URL=http://192.168.0.99:8000
AGENT_OS_HONCHO_API_KEY=local-dev
AGENT_OS_HONCHO_WORKSPACE=hermes
AGENT_OS_HONCHO_USER_PEER=yoshi
AGENT_OS_HONCHO_AI_PEER=hermes

# Optional OpenClaw gateway
AGENT_OS_OPENCLAW_GATEWAY_URL=http://<openclaw-ip>:18789
```

## APIs (v1.1)

| Endpoint | Role | Purpose |
|----------|------|---------|
| `GET /api/runtimes/health` | viewer | Probe Hermes UI/gateway, Honcho (authenticated), OpenClaw |
| `GET /api/honcho/status` | viewer | Honcho health + workspace/peers snapshot |
| `GET /api/honcho/conclusions` | operator | List conclusions from Honcho workspace |
| `POST /api/honcho/sync` | operator | Pull conclusions → `memory_entries` (`source: honcho`) |
| `GET /api/harness/bundle` | viewer | Export fleet or single-agent harness bundle JSON |
| `POST /api/runtimes/heartbeat` | agent-runtime | Upsert `runtime_instances`, update agent status |
| `GET /api/runtimes/heartbeat` | viewer | List runtime instance heartbeats |
| `GET/POST /api/agent-runs` | viewer / agent-runtime | Per-agent execution history + cost rows |
| `PATCH /api/agent-runs/:id` | agent-runtime | Update run status/output/cost |

## UI

- **Agents → Runtime tab** — Hermes link-out, last heartbeat, recent runs, export bundle
- **Settings → Harness** — Test Honcho, sync to Memory, export fleet bundle
- **Memory OS** — Sync Honcho button
- **Dashboard** — Runtime health pills (Honcho uses API key)

## Harness worker contract

1. **Pull specs:** `GET /api/harness/bundle?agent_id=1` → write files per [harness-sdk.md](../harness-sdk.md)
2. **Heartbeat:** `POST /api/runtimes/heartbeat` every 30–60s while online
3. **Runs:** `POST /api/agent-runs` on start; `PATCH /api/agent-runs/:id` on complete with `duration_ms`, `cost_usd`
4. **Memory:** continue using `/api/memory/*`; optional Honcho sync from operator UI

## Schema

- `memory_entries.source`, `memory_entries.external_id` — Honcho idempotency
- `runtime_instances` — last heartbeat per agent + runtime type
- `agent_runs` — execution log (separate from `pipeline_runs`)
